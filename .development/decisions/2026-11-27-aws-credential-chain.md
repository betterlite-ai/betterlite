No production code builds betterlite's AWS credential chain. `AwsCredentialResolver` (crates/betterlite-bedrock/src/credentials.rs L19-L25 at fe1fe676c76) is built only in tests, so every AWS path that should resolve keys, profiles, roles or web identity like LiteLLM's `BaseAWSLLM.get_credentials` either has no production caller yet or passes a stub that answers "AWS credential provider is unavailable" (Vertex workload identity in the server and the Python package, the Python Bedrock pass-through after B10166).

The chain lives in betterlite-bedrock as `credentials::chain::AwsCredentialChain`: it owns the credential cache, the native AWS sources and the secret lookup, and builds the STS client settings per call. Three roots build it once: the server's `application()` (into `Shared.aws_credentials`), each Python session that needs it, and nothing else. Callers get it as an argument or from `Shared`; no global holds it. The SDK crates below betterlite-bedrock take it from their caller.

SigV4 signing and the `Credentials` type move down into a new bottom crate, crates/betterlite-sigv4, with no betterlite dependency. Core's Polly signing is a copy of betterlite-bedrock's, and core cannot call betterlite-bedrock (betterlite-bedrock depends on core), so the shared code has to sit below both. betterlite-bedrock keeps `pub use` of `Credentials` at its old path, so its 164 importers stay as they are.

Rejected: moving the whole chain below core (about 3,250 source lines, and aws_settings and web_identity import betterlite-openai errors), putting signing in core (betterlite-secret-managers, betterlite-config, betterlite-http, betterlite-logging and betterlite-db sit below core and sign too) or in betterlite-http (betterlite-config, betterlite-secret-managers and betterlite-db sit below it), and fixing only Polly's port (the other SigV4 copies would still have no home they can reach).

B10173 builds the crate and moves Polly onto it, B10174 merges the six identical credential traits, the two secret lookup copies and the two bearer `or` chains, B10175 builds the chain and its server root, and B10176 hands it to the Python sessions. The other SigV4 copies in betterlite-secret-managers, betterlite-logging, betterlite-http, betterlite-openai, betterlite-config and betterlite-db can move onto betterlite-sigv4 later.
