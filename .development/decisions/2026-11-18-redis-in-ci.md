Every gate part installs redis-server from Debian's package, Redis 8.0.2 in trixie, so code that runs Lua scripts or other Redis commands is tested against a real server (Max). A test that needs Redis starts its own redis-server from that binary, on a unix socket in its temp folder with saving and the append-only file off, and stops it when the test ends. In a trixie container a fresh server answered its first ping 33 ms after launch. There is no shared Redis server, no service container, no serial test group and no container per test: before #2331 the shared Postgres server forced 247 database tests to run one at a time for 94 s, and its container fallback cost about 3.6 s per test. Max asked for the CI test times to be checked once the first Redis tests land.
