The dispatcher runs clippy on the packages a done answer edits before the review, in one of three shared lint lanes, and a failure goes back to the worker as a fix turn (Max agreed on 11-18 to one local clippy lane, measured first). Clippy failed 886 task PR runs and 43 merge queue runs in the flow log by 11-19, so the lane lints what the PR run lints (`cargo gate affected --edited`), not the affected packages. Each such round costs a push, a CI run of about 39 minutes and a worker fix run, and the review before it reads code that doesn't lint. A probe on three task heads with a lean shared target (no incremental, no debuginfo, no sccache) took 336 to 381 s cold and 107 to 149 s warm, caught the same errors PR CI did, kept the target at 2 to 6 GB and peaked at 8.5 GiB of compiler memory at 16 jobs. With incremental builds and debuginfo the same target reached 69 GB. About 18 done answers an hour reach the review, so one serial lane at 2 to 6 minutes a run would be full and most runs would wait. The architect started two lanes at 7 jobs each, which fit the dispatch slice. From 04:11 to 06:13 on 11-19, 17 of 58 runs waited the full 10 minutes and went to CI unlinted, while 34 of the 41 runs that got a lane found errors, so the architect raised it to three lanes. The slice had room for it: 13.6 GB anonymous memory, 8.4 GB kernel and memory pressure near 0. GATE_LINT_LANES in next-slot.sh sets the count. It goes back to 2 if a warm lane hits the 30-minute stop, or if the mean run between 08:30 and 10:30 passes 600 s (it was 317 s). The new lane starts cold, so its first runs don't count. A run waits at most 10 minutes for a lane and stops after 30, and both cases fall back to CI. Every run adds a row to tmp/lint-lanes/runs.csv (time, task, lane, wait, run seconds, exit code, packages, target GB) for the comparison. A lane target past 20 GB starts cold. A clippy exit with no compiler error line (an OOM kill, a cargo failure) falls back to CI instead of a fix turn. The dispatcher runs the lane only in a worktree that has lint-lane.sh: a worktree that merged main before the lane landed still has the old clippy command, and main's gate would run it as a full build with debuginfo into that worktree's own target.
