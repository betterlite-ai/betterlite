Tests that need a refused or a hanging address get it from one shared dev-only crate, crates/betterlite-test-ports, instead of each test binding 127.0.0.1:0, dropping the listener and using the freed port. A freed port goes back to the pool, and another test binding port 0 at the same moment can get it, so the "refused" request reaches that test's server and takes its reply. That turned scheduled run https://github.com/betterlite-ai/betterlite/actions/runs/44835631936 red on a betterlite-auth OIDC test nothing had touched.

The crate has two guards. RefusedPort keeps a socket bound to the port without listening, so a connect is refused and no other socket gets the port while the guard lives. FullListener is a listener with a full accept queue, so a connect waits. It is the first dev-only crate in the workspace. Crates take it under [dev-dependencies]; only the oracle guardrail helpers depend on it directly, since they are test tooling.

B10029 (lower crates, 45 files) and B10030 (server, CLI, binary and oracle helpers, 21 files) move the bind-then-drop sites in 62 more files and the four saturated-listener copies onto it. A new test that needs a refused address uses RefusedPort; a bare SocketAddr from a dropped listener is the bug this replaces.
