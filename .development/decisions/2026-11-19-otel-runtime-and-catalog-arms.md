Nothing outside tests built a LoggerRuntime or implemented its source traits, the config layer dropped callback_settings.otel.attributes, TraceloopLogger had no public constructor, and AgentOps fetches its JWT async while the catalog builder is sync. A new task, B10007, builds the production runtime and the per-request trace slot in betterlite-logging's otel/proxy_runtime module, and B110 builds the runtime at startup and calls LoggerCatalog::with_runtime. The slot is a tokio task_local, as betterlite-redis's request_redis_batch_scope already does and as LiteLLM keeps the root span in ContextVars; it is request context behind the injected source traits, not an outside dependency. Re-entry lives in one place: LoggingState::new captures the slot, and the success and failure handlers run inside it, so spawned logging work keeps its parent span without each spawner remembering.
